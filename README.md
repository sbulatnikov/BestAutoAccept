# BestAutoAccept

Аддон для «Аллодов Онлайн»: выполняет короткие команды из личных сообщений и сам принимает приглашения.
Замена PartyManager.

![BestAutoAccept](release/promo/Карточка%201%20·%20Обложка@2x.png)

Версия 0.10.1 (бета). Автор — NoMercy.

## Что умеет

**Команды в личке.** Игрок пишет вам в личные сообщения:

| Команда | Что делает аддон |
| --- | --- |
| `++` | приглашает его в вашу группу или отряд (полная группа сама превращается в отряд) |
| `!!` | передаёт ему лидерство |
| `??` | запускает проверку готовности |
| `##` | предлагает ему обмен |
| `>>` | ваш персонаж начинает следовать за ним |

У каждой команды есть переключатель и задержка от 0 до 30 секунд.

**Автопринятие:** приглашение в группу или отряд, приглашение в активность (с выбором всех доступных ролей),
предложение обмена (встречным предложением), место пассажира на транспорте, «На ручки!», воскрешение от игрока,
проверка готовности (с задержкой ответа от 0 до 30 секунд).

**На кого реагируем:** все, друзья, согильдейцы; чёрный список — на персонажей из него аддон не реагирует никогда.

Полное описание и ограничения — [release/description.html](release/description.html), список изменений —
[release/changes.md](release/changes.md).

## Установка

1. Скачайте `BestAutoAccept.pak` со страницы [Releases](../../releases).
2. Положите файл в `<папка игры>\data\Mods\Addons\`. При обновлении новый файл заменяет прежний.
3. Выключите PartyManager и другие аддоны с автопринятием: они будут отвечать на одни и те же приглашения.

## Управление

- ЛКМ по кнопке аддона — окно настроек, ПКМ — пауза (всё временно выключено, настройки не меняются).
- Кнопку и окно можно перетаскивать.
- `/baa` — открыть окно.

Настройки общие для всех персонажей.

## Нашли ошибку

Заведите [issue](../../issues): версия аддона, сервер, что делали и что получилось. Ошибки аддона игра пишет
в `Personal\Logs\mods.txt` — приложите строки с `BestAutoAccept`.

# Разработчикам

## Что где лежит

```
lua/       скрипты в UTF-8 (при сборке переводятся в Windows-1251)
             LibDnD.lua   перетаскивание окна и кнопки (чужая библиотека, уже в Windows-1251)
             Util.lua     строки, кэш виджетов, версия аддона
             Config.lua   настройки
             Filter.lua   на кого реагируем: друзья, гильдия, чёрный список
             Actions.lua  команды из лички и автопринятие — без интерфейса
             UI.lua       кнопка, окно настроек, всплывающие сообщения
             Main.lua     запуск, события, реакции, команда /baa
             Probe.lua    отладочный модуль: только в отладочной сборке
gen/       генератор ресурсов
             build.py     виджеты, тексты, текстуры DXT5
             assemble.py  папка аддона целиком + проверка ссылок
             pak.py       папка аддона -> BestAutoAccept.pak (ZIP с путями Mods/Addons/BestAutoAccept/...)
tools/     strip_debug.py — вырезает отладку из скриптов при сборке;
           dxtdec.py — просмотр текстур; render.py — грубый предпросмотр окна в PNG
test/      прогон логики на заглушках API игры
research/  api.md — заметки по Lua API игры, на которых построен аддон
release/   описание, краткое описание, список изменений и промо-карточки текущего выпуска (картинки — Git LFS)
```

## Сборка

Нужны Python 3 с `numpy` и `Pillow` и `rsvg-convert` (пакет `librsvg2-bin` в Debian и Ubuntu).

```
python3 gen/assemble.py out/BestAutoAccept                          ->  папка аддона
python3 gen/pak.py out/BestAutoAccept out/BestAutoAccept.pak        ->  файл для data\Mods\Addons
```

Версия задаётся в одном месте — `BAA.VERSION` в `lua/Util.lua`. Имя аддона в игре («BestAutoAccept v0.10.1»)
и `<version>` в описании аддона генератор берёт оттуда.

Отладочная сборка — с переменной `ALLODS_DEBUG=1`: в ней остаются блоки `--@debug … --@end`, строки с `--@debug`
в конце и модуль `Probe.lua` (журнал в `mods.txt`, команда `/baa debug`). Обычная сборка их вырезает, оставляя
пустые строки, — номера строк в ошибках совпадают с исходниками. В выпуск отладка не попадает.

## Тесты

```
sh test/run.sh
```

Скрипт прогоняет логику аддона на заглушках API игры дважды: без отладки и с отладкой. Нужны Python 3 и `texlua`
или `luajit` (свой интерпретатор — `LUA=<путь>`). Те же проверки и сборка запускаются в GitHub Actions на каждый
pull request.

## Правила кода

- `pcall` не используем. Ожидаемый сбой обрабатывается проверкой перед вызовом или событием игры; над проверкой —
  комментарий `-- Ожидаем: <что может не получиться> — <что делаем>`. `xpcall` — только если функция игры падает
  в обычной ситуации и иначе нельзя, с комментарием `-- Почему xpcall: …`.
- Всё неожиданное не прикрываем: оно падает в `mods.txt` со стеком, и это ошибка аддона.
- Логика (`Actions.lua`, `Filter.lua`) не трогает виджеты, интерфейс (`UI.lua`) не вызывает игровые действия напрямую.
- Виджет меняется, только если значение изменилось; никаких действий в каждом кадре.
- В `lua/` — только символы, которые есть в Windows-1251.

## Ветки и выпуски

`main` — только выпущенное. Доработка — в ветке `feature/<коротко>` или `fix/<коротко>` и через pull request.
Выпуск — слияние в `main` и тег `v<версия>`; к выпуску на GitHub прикладывается `BestAutoAccept.pak`.
